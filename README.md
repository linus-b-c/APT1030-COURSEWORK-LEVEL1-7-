🚀 Project Overview
The project is divided into seven progressive modules, each comparing different programming languages (Python, Java, and C++) to evaluate their strengths in security, performance, and scalability.

📂 Level-by-Level Breakdown
[Level 1] Syntax, Semantics, and Program Correctness
Context: eCitizen Login Validation.

Concepts: Compilation vs. Interpretation, Runtime vs. Logical Errors.

Task: Hardcoded credential validation ("adminKE" / "254Secure").

[Level 2] Data Types and Type Systems
Context: SACCO Member Financial Records.

Concepts: Static vs. Dynamic typing, Type Coercion, Memory Safety.

Task: 6-month contribution calculator with a "Critical Test" for type violations.

[Level 3] Control Flow and Decision Systems
Context: Drought Advisory Logic (Machakos County).

Concepts: Nested conditions, switch statements, logic optimization.

Task: Rainfall (mm) and Temperature-based agricultural advisory system.

[Level 4] Abstraction and Modularity
Context: NHIF Claims Processing.

Concepts: Object-Oriented Programming (OOP), Encapsulation, Modularity.

Task: Patient class with automated 10% co-payment calculation logic.

[Level 5] Paradigm Comparison
Context: Ride-Hailing Pricing Engine (Nairobi).

Concepts: Procedural vs. OOP vs. Functional (Lambda).

Task: Multi-paradigm implementation of a base fare + distance pricing model.

[Level 6] Scope, Memory, and Error Handling
Context: Patient Record Access Control.

Concepts: Stack vs. Heap, Lexical Scope, Exception Handling.

Task: Role-based access security (Doctor role verification) and scope lifetime experiments.

[Level 7] Capstone: Mini DSL Implementation
Context: Mobile Money (M-Pesa style) Rule Engine.

Concepts: Domain-Specific Languages (DSL), Tokenization, Parsing, Interpreters.

Task: A Python-based interpreter that parses and executes natural language financial rules.
